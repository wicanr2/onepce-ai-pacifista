狀態：READY（M1）。本檔是規則表；程式照本檔寫，不對照任何模擬器的函式寫

## 1. 暫存器與旗標

- `A`、`X`、`Y`、`S`（8-bit）、`PC`（16-bit）、`P`。
- `P` 位元：`C=0x01 Z=0x02 I=0x04 D=0x08 B=0x10 T=0x20 V=0x40 N=0x80`。`T` 是 HuC6280 的
  memory-operand 旗標（`SET` 設定；每條指令開始前先取樣再清除，所以只影響**緊接的一條**）。
- 上電：`I=1`，`D=0`，`T=0`；`PC` 由 `$FFFE/$FFFF` 取；`A/X/Y/S` 不定（本專案上電固定 0，
  並在 spec 標明這是 remake 決定，不是硬體事實）。

## 2. 位址空間

- logical 16-bit，8 頁 × 8 KB，`MPR[page]` 選 bank（`docs/spec/address-model.md`）。
- zero page 是 logical `$2000–$20FF`，stack 是 `$2100–$21FF`（`S` 遞減）。zero page 的
  16-bit 讀（`(zp)`、`(zp,X)`、`(zp),Y`）在 `$FF` 處**回繞到 `$00`**，不進 `$2100`。
- 向量：reset `$FFFE`、NMI `$FFFC`、timer `$FFFA`、IRQ1 `$FFF8`、IRQ2／BRK `$FFF6`。
- `TAM #mask`：mask 每個為 1 的位元對應的 MPR 都寫入 `A`；mask=0 不動作。
  `TMA #mask`：把 mask 選到的 MPR **OR 起來**放進 `A`；mask=0 回傳最後一次 TAM 寫入的值。
- 上電 `MPR7=0`；其餘 MPR 硬體不定，本專案上電固定 0（remake 決定）。

## 3. 位址模式（本專案的命名）

`imp`、`acc`、`imm`、`zp`、`zpx`、`zpy`、`abs`、`absx`、`absy`、`ind`（`JMP (abs)`，跨頁正常）、
`absxind`（`JMP (abs,X)`）、`indx`（`(zp,X)`）、`indy`（`(zp),Y`）、`zpind`（`(zp)`）、
`rel`、`zprel`（BBR/BBS：zp 位址＋相對位移）、`immzp`／`immzpx`／`immabs`／`immabsx`（TST：
立即值＋目標位址）、`blk`（block transfer：來源、目的、長度各 16-bit，指令共 7 bytes）。

## 5. 語意規則

| # | 規則 | 等級 |
|---|---|---|
| C1 | `T=1` 時 `ADC/SBC/AND/EOR/ORA` 的「累加器」改為記憶體 `zp[X]`（logical `$2000+X`）：讀它、與運算元運算、寫回它、設 N/Z（ADC/SBC 另設 C/V）；`A` 不變 | 已證實 |
| C2 | `ADC/SBC` 支援 decimal（`D=1`）；HuC6280 的 decimal 模式 N/Z/V 依結果設定（沒有 6502 的旗標怪癖） | 強推論（公開文件） |
| C3 | 中斷進入：push PC、push P（B 清除；BRK 時 B 設定），清 D 與 T，設 I，跳向量。優先序：**timer > IRQ1 > IRQ2**；`I=1` 時全部擋住；`$1402` 的位元遮罩（bit0=IRQ2、bit1=IRQ1、bit2=timer，1=disable） | 已證實 |
| C4 | 中斷在**每條指令結束後**檢查；`CLI` 後的下一條指令執行完才會進中斷 | 已證實 |
| C5 | timer：`$0C00` 寫 reload（7 bit），`$0C01` bit0 啟用；啟用邊緣時重載 counter 與分頻器；分頻器以 **3 個主時脈為一步、每 1024 步** counter 減 1（等於 1024 個高速 CPU 週期；低速時每個 CPU 週期算 4 步），為 0 時再過一輪 → 重載並發 timer IRQ；`$1403` 任何寫入清 timer IRQ；`$0C00` 讀回 counter（到期前最後 5 步讀到 `$7F`） | 已證實 |
| C6 | `CSL`/`CSH`：CPU 時脈 1.79／7.16 MHz；上電是**低速**。本專案第一版所有時序以「CPU 週期」計，高低速只影響 CPU 週期對主時脈的換算（VDC 用主時脈） | 已證實 |
| C7 | block transfer：先 push Y、A、X，做完 pop 回來（所以 A/X/Y 不變）；TII src++ dst++；TDD src-- dst--；TIN src++ dst 固定；TIA src++ dst 交替（+1,-1,+1…）；TAI src 交替 dst++；長度 0 視為 65536 | 已證實 |
| C8 | `ST0/ST1/ST2` 直接寫 VDC 埠 `$0000/$0002/$0003`，不看 MPR | 已證實 |
| C9 | `JMP (abs)` 跨頁正常；`JSR` push 最後一個運算元位元組的位址；`RTS` pop 後 +1；`BSR` push `PC-1`（下一指令位址減 1，與 JSR 相同語意） | 已證實 |
| C10 | 讀 `MPR=$FF` 頁：`$0000–03FF` VDC、`$0400–07FF` VCE、`$0800–0BFF` PSG（讀回 I/O buffer）、`$0C00–0FFF` timer、`$1000–13FF` 手把埠、`$1400–17FF` IRQ 暫存器（`$1402` disable mask、`$1403` 讀 active、寫清 timer）、其餘 `$FF` | 已證實 |
| C11 | 讀 `$1000` 手把埠：bit7=無 CD-ROM（1）、bit6=地區（日本機=1? 依文件：TurboGrafx 為 0、PC Engine 為 1）、bit5–4=1、bit3–0=手把資料 | 已證實（bit 配置）；地區位元的值以 Nectaris 實測裁決 |

## 6. 週期模型

每條指令的週期數 = 表中「基本週期」（含所有記憶體存取與內部週期）。
分支成立 +2；`BBR/BBS` 成立 +2；page-cross **不加**（HuC6280 沒有 6502 的 +1）。
block transfer：`17 + 6 × 長度`。VDC／VCE 讀寫多 1 週期（C10 的兩區）。
週期數用來驅動 timer（C5）與交給匯流排的「主時脈進位」（高速 ×3、低速 ×12）。

基本週期表（摘要，完整在 `opcodes.go`）：LDA/LDX/LDY/STA… `imm 2、zp 4、zpx 4、abs 5、absx 5、absy 5、indx 7、indy 7、zpind 7`；
`INC/DEC/ASL/LSR/ROL/ROR/TSB/TRB` 記憶體 `zp 6、zpx 6、abs 7、absx 7`；`RMB/SMB 7`；`BBR/BBS 6(+2)`；
`JMP abs 4、ind 7、absxind 7`；`JSR 7、RTS 7、RTI 7、BSR 8`；`PHx 3、PLx 4`；`BRK 8`；
`TAM 5、TMA 4`；`ST0–2 4`（＋VDC 存取 stall 1）；`TST immzp 7、immabs 8、immzpx 7、immabsx 8`；`CSL/CSH 3`；`SET 2`；
`SXY/SAX/SAY 3`；`CLA/CLX/CLY 2`；`Txx 2`；`NOP 2`；`CLx/SEx 2`。
實作採**逐存取計時**：每次記憶體讀寫 1 週期、內部週期用 `Idle`；表中的數字是交叉核對用的
斷言（`cycles_test.go` 對 256 個 opcode 逐一驗證計數等於表值）。存取與內部週期的排列
（例如 `zp` 模式是「讀位址、idle、存取」）取自實測行為，中斷取樣在**每個週期**進行，
所以 `CLI`／`PLP` 之後的中斷會晚一條指令（C4）。

## 7. 介面

```go
type Bus interface {
    Read(logical uint16) uint8         // 每次呼叫本身就是 1 個 CPU 週期
    Write(logical uint16, v uint8)
    Peek(logical uint16) uint8         // 不計時、無副作用（trace／測試用）
    WriteVDCPort(port uint8, v uint8)  // ST0/ST1/ST2
    SetMPR(mask, v uint8); GetMPR(mask uint8) uint8   // TAM／TMA
    SetSpeed(fast bool)                // CSH／CSL
    Idle()                             // 1 個無存取的內部週期
    PendingIRQ() uint8                 // bit0 IRQ2、bit1 IRQ1、bit2 timer（已套用 $1402 遮罩）
}
type CPU struct{ A, X, Y, S, P uint8; PC uint16; Cycles uint64; ... }
func (c *CPU) Step() int   // 執行一條指令（含隨後的中斷檢查），回傳週期數
func (c *CPU) Reset()
```

trace hook：`Step` 前可取得 `{PC, opcode, A, X, Y, S, P, MPR}`；`observe` 層用它做 exec watch 與
trace。CPU 不知道 frame、scanline。

## 8. 驗收

- **內部自洽**：`opcodes_test.go` 對 256 筆表做完整性檢查（無空格、長度與模式一致）；每類指令
  的旗標／結果單元測試；T flag、block transfer 五種方向、TAM/TMA 多位元、zero page 回繞、
  中斷優先序與 `$1402` 遮罩、timer 分頻各一條。
- **對 oracle**：`tools/oracle/mesen2_trace_probe.lua` 在 Mesen2 對 Nectaris 開機錄前 N 條指令
  的 `PC`＋opcode（每 1000 條附完整暫存器與 MPR）；`internal/huc6280` 搭最小匯流排（ROM＋RAM＋
  I/O stub）跑同樣 N 條，**PC＋opcode 序列的 SHA-256 相同**，抽樣點暫存器相同。fixture 只在
  本機（`ONEPCE_FIXTURES`），沒有就 skip。
- 未知：C2 的 decimal 旗標細節、C11 的地區位元，遇到 Nectaris 用到時以 trace 裁決並補勘誤。

## 9. 對照結果（2026-09-04，Nectaris 開機 trace，200,000 條）

- 前 **165,454** 條逐指令相同（含七個 frame 的 VBlank 等待、MPR 切換、block transfer、CLI 後的
  中斷延遲）。週期表與逐存取計數在 256 個 opcode 上互相吻合（`cycles_test.go`）。
- 第 165,454 條分歧：oracle 在此進 timer 中斷（向量 `$FFFA` → `$E0CB`），本核心晚了約兩百條指令。
  兩邊的指令序列相同、**週期數不同**：oracle 在 VRAM 上傳期間讓 CPU 等待 VDC 的寫入佇列
  （`vdc-vce.md` §8 第一列的刻意差異），累積的等待把 timer 到期推到不同的指令上。
  這不是 CPU 錯誤；要消除得實作 VRAM 存取時序。
- `machine/trace_test.go` 因此以 `ONEPCE_TRACE_LIMIT`（預設 160,000）為界。
